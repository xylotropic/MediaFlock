# Provider capability and verification matrix

Reviewed 2026-10-02 against the official API schema and resource guides. Isolated fixture tests verify serializer/response behavior, not real OAuth or native publication. No live Post for Me account, paid model call or social post was used during verification.

| Capability            | Implementation                                                                                  | Verification                                          | Limits                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------- |
| Auth and base URL     | Bearer key; `https://api.postforme.dev/v1`                                                      | Documentation + fixture                               | Key must be supplied by owner                                  |
| Account authorization | `social-accounts/auth-url`, posts/feeds requested, fixed project callback                       | Documentation + fixture                               | Native consent and real compatibility untested                 |
| Multiple accounts     | All pages; exact external binding/platform; connected results only                              | Database + fixture                                    | Imported permissions/types remain unknown                      |
| LinkedIn              | Quickstart organization flow for profiles/pages; own credentials may use personal via API       | Documentation + fixture                               | Connection type does not prove native account type             |
| Media upload          | Upload URL, pinned public HTTPS upload, byte checksum, provider-hosted media                    | Documentation + fixture; private storage live checked | Real provider upload untested; files limited to 50 MiB         |
| Scheduling            | One account per immutable provider-managed job                                                  | Documentation + fixture                               | Local external ID is not provider idempotency                  |
| Publication           | Matching per-account result with native post ID                                                 | Documentation + fixture                               | Acceptance/processed status alone is not publication           |
| Cancellation          | DELETE request followed by explicit uncertainty unless authoritative final evidence exists      | Documentation + fixture                               | DELETE acknowledgement/404 is not proof of cancellation        |
| Rescheduling          | Confirm old cancellation, request new approval/time                                             | Database + fixture                                    | Uncertain old jobs prevent replacement                         |
| Feeds and metrics     | Paginated account feed with `expand=metrics`                                                    | Documentation + fixture                               | Per-account permissions and metric availability vary           |
| Webhooks              | Disabled ingestion endpoint; deduplicated hints only in trusted internal service                | Fixture                                               | Documented authenticity mechanism is not established           |
| Retry/recovery        | Durable attempt, fencing, read/reconciliation after ambiguity                                   | Database + fixture + process restart                  | No exactly-once external guarantee                             |
| YouTube video/Short   | Same channel; video privacy/title; Short media criteria                                         | Documentation + validation test                       | Native Short classification/publication untested               |
| Instagram             | Professional type owner-reviewed; reel versus timeline mapping                                  | Documentation + validation test                       | Stories excluded from format set                               |
| Facebook              | Owner-reviewed Page; video/image/text timeline                                                  | Documentation + validation test                       | Personal profiles not assumed supported                        |
| TikTok                | Multiple owner-reviewed accounts; public/private, direct publication, auto music off by default | Documentation + validation test                       | Draft-upload mode excluded                                     |
| LinkedIn/X            | Video/image/text with owner-reviewed formats                                                    | Documentation + fixture                               | Provider/native size and entitlement limits may reject content |

The permitted settings are in `packages/publishing/validation.ts`. The immutable revision contains effective settings; provider/account defaults are never merged at dispatch. All target platforms have implemented adapter mappings, but all actual provider/network account flows remain untested until the owner connects them.

Sources: [API documentation](https://api.postforme.dev/docs), [account callbacks](https://www.postforme.dev/resources/handling-account-connection-redirects-and-webhooks), [OAuth interception](https://www.postforme.dev/resources/intercepting-the-oauth-flow), [LinkedIn connection types](https://www.postforme.dev/resources/understanding-linkedin-connection-types), [advanced configuration](https://www.postforme.dev/resources/advanced-posting-configurations), [post results](https://www.postforme.dev/resources/getting-post-results), [feeds/pagination](https://www.postforme.dev/resources/pagination-account-feeds), [YouTube Shorts](https://support.google.com/youtube/answer/15424877).
